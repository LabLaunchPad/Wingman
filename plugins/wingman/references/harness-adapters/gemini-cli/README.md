# Wingman for Gemini CLI

Added 2026-07-27, part of the founder-directed override of Wingman's own 3x-declined
"full agent-agnostic rewrite" stance (see `docs/status/ARCHITECTURE.md` §8f and `docs/status/PROJECT.md`'s
2026-07-27 decisions-log entry) — the founder explicitly asked to proceed, given fresh capability
research replacing the earlier, less-precise pass. Of the 6 harnesses in scope, Gemini CLI is the
**strongest capability match** found: real parallel subagent dispatch, a real structured
multi-choice question tool, and hooks that can genuinely block a tool call — the only real gap is
the plan-gate.

## Verification-status legend

Same 4-tier legend used throughout `references/harness-adapters/`:
- **built + tested** — created and confirmed working in this repo's own sandbox.
- **structurally verified (live install)** — confirmed against a real, installed instance of the
  target harness.
- **authored, unverified** — a faithful, best-effort translation checked against public
  documentation, never run against a live install.
- **not attempted, documented why** — deliberately skipped, with the concrete reason stated inline.

## What's here

- `gemini-extension.json` — **authored, unverified**. Schema (name/version/description required;
  contextFileName optional, defaults to GEMINI.md) confirmed via a dedicated 2026-07-27 schema-
  verification research pass, but never loaded by a real Gemini CLI install (none available in this
  sandbox).
- `GEMINI.md` — **authored, unverified**. Uses Gemini CLI's real `@file.md` import syntax
  (confirmed schema) to pull in a curated subset of the shared skills, rather than relying on
  autodiscovery (Gemini CLI has no confirmed native skill-discovery convention of its own, unlike
  Codex CLI/OpenCode).
- `agents/boardroom-*.md` (8) — **authored, unverified**. Markdown + YAML frontmatter
  (name/description required, model optional) — the real, confirmed subagent schema, structurally
  closer to Wingman's own canonical agent format than either Codex CLI's TOML or OpenCode's
  permission-block frontmatter. `model:` is set only for the 2 opus-tier seats (`ciso`, `cto`), with
  the same "set this to your install's strongest available model" honesty pattern Codex CLI's
  adapter already uses — no unconfirmed specific Gemini model tier is asserted. `tools:` is
  deliberately omitted (no confirmed Gemini CLI tool-name mapping for Read/Grep/Glob/Bash).
- `commands/wingman/*.toml` (24) — **built + tested** (generated, `--check`-verified in this
  sandbox; the file-writing mechanism itself is real and repeatable, though no live Gemini CLI
  install has loaded the output). Generated by `generate-harness-adapters.mjs`'s new `'toml'`
  commands mode from the canonical `plugins/wingman/commands/**` source — `prompt` +
  `description` fields, no `name` field (Gemini CLI derives the invocation name from the file path;
  nesting under `commands/wingman/` reproduces this plugin's own `/wingman:<name>` convention).
  `$ARGUMENTS` is mechanically rewritten to Gemini's real `{{args}}` placeholder.
- `hooks/hooks.json` + `hooks/secret-guard.mjs` — **authored, unverified**. Wires the real,
  confirmed `BeforeTool` event (not `PreToolUse`/`PostToolUse` — an earlier general research pass
  had this wrong; corrected by a dedicated 2026-07-27 schema-verification pass) to a self-contained
  port of `plugins/wingman/hooks/secret-guard.mjs`'s `decide()` logic. The exact stdin payload
  field names a Gemini CLI `BeforeTool` command hook receives were not pinned down at that level of
  detail, so this script reads several plausible field-name variants and fails **open** on anything
  it doesn't recognize — it can under-block, never over-block on a guess.
- `hooks/prompt-guard.mjs` — **authored, unverified** (2026-07-27 completeness pass). Wired to
  `BeforeModel` — the closest confirmed real event to Claude Code's `UserPromptSubmit` (Gemini CLI's
  taxonomy has no discrete "prompt submitted" event distinct from a model call), a self-contained
  port of `plugins/wingman/hooks/prompt-guard.mjs`'s injection-pattern scan. Same defensive,
  fail-open posture as `secret-guard.mjs`'s port, for the same reason.
- `hooks/plan-gate.mjs` — **authored, unverified**, the one genuinely new piece of hook logic in
  this adapter (every other primitive here is a port). Gemini CLI has a real Plan mode, but exiting
  it auto-escalates straight to YOLO mode with no discrete, interceptable "plan approved" event —
  the closest gate of any evaluated harness, still real capability gap. This hook runs the same
  approved-checkpoint check `boardroom-checkpoint.mjs` runs, on every `BeforeAgent` turn instead of
  one specific transition (a coarser proxy, disclosed as such). See its own header comment for the
  full reasoning, and `evals/cases/plan-gate-mode-switch-intercept.md` for its eval case.
  `plugins/wingman/scripts/dod-pre-push-check.mjs` (wired via `install-git-hooks.mjs`) is the
  second, independent backstop this gate's weakness makes necessary.
- `shared/.agents/skills/` (40 skills) — see `references/harness-adapters/README.md`'s top-level
  entry; Gemini CLI is a third contributor to the same generated shared output, pulled in via
  `GEMINI.md`'s `@file.md` imports rather than native autodiscovery.

## Capability profile

| Primitive | Status | Disclosed substitute |
|---|---|---|
| Hooks | ✅ confirmed (`BeforeTool` et al., can block) | n/a — real capability |
| Plan-gate | ⚠️ weak — real Plan mode, but exit auto-escalates to YOLO, no discrete transition event | `hooks/plan-gate.mjs` (coarse per-turn proxy) + `dod-pre-push-check.mjs` (git-push backstop) |
| Parallel dispatch | ✅ confirmed (isolated-context subagents, parent consolidates) | n/a — real capability |

## Deliberately not attempted here (and why)

- **Live model inference / live install confirmation.** No Gemini CLI account or credential exists
  in this sandbox (`docs/HUMAN-TODOS.md`'s open item, same class of gap as Codex CLI's). Every
  artifact above is either mechanically generated-and-verified (the `commands/wingman/*.toml`
  files, `--check`-clean) or authored against confirmed schemas but never loaded by a real install.
- **A confirmed exact stdin payload schema for `BeforeTool`/`BeforeAgent` hook commands.** The
  2026-07-27 research pass confirmed the event names and the outer `hooks.json` shape, but not the
  field-level JSON a command hook actually receives on stdin — `hooks/secret-guard.mjs` is written
  defensively (fails open on an unrecognized shape) specifically because of this gap.

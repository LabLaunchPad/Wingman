# Wingman for OpenHands

Added 2026-07-27, Phase 3 of the founder-directed 6-harness build (Phase 1: descriptor-driven
generator refactor, `0.7.12`; Phase 2: Gemini CLI adapter, `0.7.13`). **Scope is deliberately
narrower than the Gemini CLI adapter**: OpenHands' capability findings below come from the
2026-07-27 general 6-harness capability-matrix pass, not a dedicated field-level schema-verification
pass the way Gemini CLI got — see `harness-targets/openhands.mjs`'s own header comment. Two real
gaps are disclosed rather than papered over with an invented schema: no Boardroom-persona file
format, and no exact hooks-config file schema, were independently confirmed at the field level in
this pass.

## Verification-status legend

Same 4-tier legend used throughout `references/harness-adapters/`:
- **built + tested** — created and confirmed working in this repo's own sandbox.
- **structurally verified (live install)** — confirmed against a real, installed instance of the
  target harness.
- **authored, unverified** — a faithful, best-effort translation checked against public
  documentation, never run against a live install.
- **not attempted, documented why** — deliberately skipped, with the concrete reason stated inline.

## What's here

- `microagents/repo.md` — **built + tested** (generated, `--check`-verified in this sandbox — the
  file-writing mechanism is real and repeatable, though no live OpenHands install has loaded the
  output). All 24 canonical `/wingman:*` commands, one per section, generated by
  `generate-harness-adapters.mjs`'s existing `'folded'` commands mode (same mode Codex CLI's
  `AGENTS.md` fallback uses) — OpenHands has no confirmed user-authored slash-command/prompt-
  template file primitive, so each command is written as a section to paste into (or reference
  from) a project's own `repo.md`, OpenHands' own confirmed-real, automatically-loaded
  repository-instructions file.
- `shared/.agents/skills/` — see `references/harness-adapters/README.md`'s top-level entry;
  OpenHands is a fourth contributor to the same generated shared output. No confirmed native
  skill-discovery convention exists for this exact shape in OpenHands, so this is offered for
  manual copy/reference (same honest posture Gemini CLI's adapter takes), not claimed as
  auto-discovered.

## Deliberately not attempted here (and why)

- **A Boardroom-persona adapter (`agents/boardroom-*.md` or equivalent).** Unlike Gemini CLI's real,
  confirmed Markdown+YAML subagent schema, no equivalent persona-definition file format for OpenHands
  was independently confirmed in this pass. Inventing one would risk exactly the kind of unconfirmed-
  schema fabrication this project's own discipline exists to avoid. `check-harness-adapter-drift.mjs`
  simply skips OpenHands for the persona-drift check as a result (no `agents` block in
  `harness-targets/openhands.mjs`) — an honest omission, not a silent gap. Tracked as an open item
  in `docs/HUMAN-TODOS.md` pending a real OpenHands install/account to confirm the real schema
  against.
- **A hooks-config wiring file** (the OpenHands equivalent of Gemini CLI's `hooks/hooks.json` or
  Codex CLI's `.codex/hooks.json`). The capability-matrix pass confirmed OpenHands' hook *event
  names* map closely to Claude Code's own taxonomy, but not the exact config file location, field
  names, or command-invocation shape a real hook definition needs — building one now would be a
  guess dressed up as a port. Left for a follow-up dedicated schema-verification pass, matching the
  standard Gemini CLI's own hooks were held to.
- **Live model inference / live install confirmation.** No OpenHands account or credential exists in
  this sandbox (`docs/HUMAN-TODOS.md`'s open item, same class of gap as Codex CLI's and Gemini
  CLI's).

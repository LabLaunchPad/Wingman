# Wingman for Cursor

Added 2026-07-27, Phase 5 (and last) of the founder-directed 6-harness build (Phase 1:
descriptor-driven generator refactor, `0.7.12`; Phase 2: Gemini CLI, `0.7.13`; Phase 3: OpenHands,
`0.7.14`-`0.7.15`; Phase 4: Cline, `0.7.17`). Sequenced last on purpose — of the 6 harnesses, Cursor
has the **weakest capability match**: only 3 narrow hook lifecycle points (no generic PreToolUse
equivalent), a Plan Mode whose exit is UI-click-only with no interceptable event, and no question
tool at all. Like OpenHands/Cline, capability findings come from the general capability-matrix pass,
not a dedicated field-level schema-verification pass.

## Verification-status legend

Same 4-tier legend used throughout `references/harness-adapters/`:
- **built + tested** — created and confirmed working in this repo's own sandbox.
- **structurally verified (live install)** — confirmed against a real, installed instance of the
  target harness.
- **authored, unverified** — a faithful, best-effort translation checked against public
  documentation, never run against a live install.
- **not attempted, documented why** — deliberately skipped, with the concrete reason stated inline.

## What's here

- `.cursor/commands/*.md` (32) — **built + tested** (generated, `--check`-verified in this sandbox;
  the file-writing mechanism is real and repeatable, though no live Cursor install has loaded the
  output). Cursor's real, documented custom-command convention — each file invocable as a slash
  command — using the existing `'perFile'` commands mode, same shape as OpenCode's/Cline's own
  adapters.
- `.cursor/rules/*.mdc` (40) — **authored, unverified** (2026-07-27 completeness pass — previously
  left out of scope, now a real translation, not just the raw `SKILL.md` offered for reference).
  Generated by a new `skills.mdcOutDir`/`mdcFrontmatter` mechanism in
  `generate-harness-adapters.mjs`: each skill's `description` is carried into the real, documented
  Cursor Project Rules frontmatter shape (`description`/`globs`/`alwaysApply`), with
  `alwaysApply: false` and empty `globs` — Cursor's own "Agent Requested" mode, where the agent reads
  `description` and decides whether to pull the rule in, the closest real analog to Claude Code's own
  description-triggered skill auto-invocation.
- `shared/.agents/skills/` — see `references/harness-adapters/README.md`'s top-level entry; Cursor
  also contributes to the same generated shared output (the raw `SKILL.md`, for manual reference
  alongside the real `.mdc` translation above).
- `.cursor/hooks.json` + `.cursor/hooks/secret-guard.mjs` — **authored, unverified** (2026-07-27
  completeness pass). Wires Cursor's 2 blockable lifecycle events (`beforeShellExecution`,
  `afterFileEdit`) to a self-contained port of `secret-guard.mjs`'s `decide()` logic, per Cursor's
  publicly documented Hooks schema (`.cursor/hooks.json`, a command hook reading JSON on stdin,
  returning `{"permission": "allow"|"deny", ...}`). The exact stdin field names were not confirmed
  against a live install, so the script reads several plausible variants and fails **open** on
  anything unrecognized — same defensive posture Gemini CLI's port takes. `afterFileEdit` fires
  after the write already happened (documented Cursor limitation, not this port's own gap) — it
  can only advise, not block, so a founder still sees a loud warning even though the edit landed.
  `beforeMCPExecution` is left genuinely unwired (disclosed, not invented — no MCP tool call in this
  plugin's own surface needs gating there).

## Capability profile

| Primitive | Status | Disclosed substitute |
|---|---|---|
| Hooks | ⚠️ only 3 narrow lifecycle points (`beforeShellExecution`/`beforeMCPExecution`/`afterFileEdit`), no generic PreToolUse equivalent | `.cursor/hooks.json` + `secret-guard.mjs` wired for the 2 blockable events (authored, unverified) |
| Plan-gate | ⚠️ real Plan Mode exists, but the transition out of it is UI-click-only — no hook fires | `plugins/wingman/scripts/install-git-hooks.mjs` + `dod-pre-push-check.mjs` (git-push backstop) — same fallback every other gapped harness in this build uses |
| Parallel dispatch | ✅ confirmed genuine: up to 8 parallel, worktree-isolated background agents | n/a — real capability; an 8-seat Boardroom (7 core + Design) fits in one batch exactly |
| Question tool | ❌ none — forum feature requests only, not shipped | plain conversational text, options listed in prose |

## Deliberately not attempted here (and why)

- **A Boardroom-persona adapter.** No confirmed persona-definition file format exists for Cursor's
  background agents (they're driven internally, not via a user-authored config file) — inventing one
  would be a fabrication, not a port.
- **Live model inference / live install confirmation.** No Cursor account or credential exists in
  this sandbox (`docs/HUMAN-TODOS.md`'s open item, same class of gap as every other harness in this
  build) — the hooks.json wiring and `.mdc` frontmatter shape above are checked against Cursor's own
  public docs, not a live install.

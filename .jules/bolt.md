## 2026-07-27 - [Flat Accumulator Pattern for Recursive File System Traversals]
**Learning:** In Node.js utility functions performing recursive file-system traversals (like `listFilesRecursive` in `dod-structural-gate.mjs` and OpenCode's `dod-gate.js`), using `.concat()` on recursively returned arrays leads to significant memory garbage collection (GC) overhead and overhead from array copying. Moving to a flat accumulator pattern (passing an accumulator array parameter like `results = []`) optimizes memory footprint and improves CPU efficiency.
**Action:** Always utilize a flat accumulator parameter for recursive folder scans / I/O operations instead of building and concatenating sub-arrays.

## 2026-07-25 - [DoD Test-Presence Fallback Scan, Once Per Call]
**Learning:** `checkTestPresence`'s fallback (`anyTestFileReferencesSource`) re-scanned and re-read every file under `test/`/`tests/`/`__tests__/` from scratch for each changed source file that needed it, an O(changed-files × test-files) disk-I/O cost on a push touching many files. Loading and reading every test file once per `checkTestPresence()` invocation (a local array scoped to that call, not module-level cache state) drops this to O(test-files) while staying trivially safe under repeated calls in the same process — no shared mutable state to reset means no reset-forgotten footgun.
**Action:** Prefer a call-scoped local cache over a module-level cache-plus-manual-reset pattern when the caching only needs to live for the duration of one function invocation — it gets the same I/O win without introducing state that can leak across calls if a reset is ever missed.

## 2026-07-22 - [Check-Fixtures Async I/O]
**Learning:** Running multiple parallel processes (like 49 setup-fixture bash scripts via an async worker pool in Node.js) while making blocking synchronous file-system calls (`readFileSync`, `readdirSync`, `mkdtempSync`, `rmSync`) inside each task blocks the single-threaded event loop. This degrades parallel execution performance and process management latency. Replacing them with non-blocking async promises (`node:fs/promises` APIs) unblocks the event loop completely, optimizing signal detection and file manipulation during heavy parallel task executions.
**Action:** Always prefer promise-based async I/O (`fs/promises`) inside any concurrent or parallel process execution loop (such as child process execution pools) in Node.js to keep the event loop highly responsive.

## 2026-07-22 - [Check-Fixtures Async I/O]
**Learning:** Running multiple parallel processes (like 49 setup-fixture bash scripts via an async worker pool in Node.js) while making blocking synchronous file-system calls (`readFileSync`, `readdirSync`, `mkdtempSync`, `rmSync`) inside each task blocks the single-threaded event loop. This degrades parallel execution performance and process management latency. Replacing them with non-blocking async promises (`node:fs/promises` APIs) unblocks the event loop completely, optimizing signal detection and file manipulation during heavy parallel task executions.
**Action:** Always prefer promise-based async I/O (`fs/promises`) inside any concurrent or parallel process execution loop (such as child process execution pools) in Node.js to keep the event loop highly responsive.

## 2026-07-23 - [DoD Test Presence Cache-Optimized Walk]
**Learning:** Checking test presence for a batch of modified source files via recursive directory scanning (`readdirSync`) and synchronous file reading (`readFileSync`) across multiple directories (`test/`, `tests/`, `__tests__/`) repeatedly incurs $O(N \times M)$ disk I/O operations, where $N$ is the number of changed files and $M$ is the number of test files. In large PRs, this results in significant delays. Introducing module-scoped Map caches for file structures and file content, reset at the beginning of each checking pass, reduces disk I/O to $O(1)$ walks and single reads per file, drastically speeding up verification gates.
**Action:** Always introduce session-scoped or pass-scoped file-system caches when performing synchronous multi-file checks/validation patterns in Git hooks or CLI validators to avoid high I/O overhead.
